# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Demonstration of Clean Architecture in Spring Boot: a reactive movie-search app over the external
[OMDB API](https://www.omdbapi.com) that persists searches and results locally. One repository, two
independent builds: `backend/` (Gradle, Kotlin, Spring WebFlux) and `frontend/` (npm, Angular).

The Gradle root project only includes `:backend` — the frontend is *not* part of the Gradle build.

## Commands

### Backend (run from repository root)

```bash
./gradlew build                  # compile + all tests
./gradlew :backend:test          # tests only
./gradlew detekt                 # static analysis (autoCorrect is enabled)
./gradlew generateOpenApiDocs    # boots the app, writes backend/build/openapi/openapi.yaml
./gradlew bootRun                # run on http://localhost:8080

# single test class / method
./gradlew :backend:test --tests "clean.architecture.omdb.service.SearchServiceTest"
./gradlew :backend:test --tests "*SearchServiceTest.when saving search*"
```

`./gradlew build detekt generateOpenApiDocs` is exactly what CI runs — use it before pushing.

Requires `backend/src/main/resources/secrets.properties` (gitignored) containing:

```properties
omdb.api-key=<key>
```

Without it the app starts but OMDB calls fail. CI writes this file from the `OMDB_API_KEY` secret.

### Frontend (run from `frontend/`)

```bash
npm ci
npm start                        # ng serve on :4200, proxies /api -> localhost:8080
npm run lint
npm test -- --watch=false
npm run build                    # -> frontend/dist/omdb-frontend

# single spec file / single test name
npm test -- --watch=false --include src/app/services/api.service.spec.ts
npm test -- --watch=false --filter "saveSearch"
```

### Full stack

```bash
docker compose up --build        # frontend on :80 (nginx), backend on :8080
```

## Generated / CI-owned files — do not hand-edit

- `openapi/openapi.yaml` — regenerated by `generateOpenApiDocs` and committed by CI. Change the
  Swagger annotations on the controllers instead.
- `release/backend.jar`, `release/frontend.zip` — build artifacts committed to `master` by
  `.github/workflows/push-artifacts.yml`.

## Backend architecture

Layering is deliberate and the whole point of the repository; keep changes inside the right layer.

```
controller/  @RestController — HTTP only: validate input, serialize domain models, Swagger annotations
service/     @Service        — thin bridge controller -> use cases; owns dispatcher switching
domain/      usecase/ model/ — all business logic and rules; framework-independent, no Spring web/data types
data/        @Component/@Service — data facades; the only place that knows about DB and remote shapes
  local/     R2DBC Coroutine CRUD repositories + entity/ (table rows)
  remote/    ApiClient (WebClient) + model/ (OMDB response DTOs)
  mapper/    toDomain() / toEntity() extension functions
exception/   GlobalExceptionHandler — RFC 7807 ProblemDetail responses
```

Rules that the existing code follows and that reviews enforce:

- **Business logic lives in use cases, not services.** `SearchService` does nothing but
  `withContext(dispatcher.io) { useCase(...) }`. Adding logic there instead of a use case defeats the
  fast-unit-test strategy.
- **Never touch `Dispatchers.IO` directly.** Inject `DispatcherProvider` so tests can substitute
  `UnconfinedTestDispatcher`.
- **Repositories are facades.** `MovieRepository` / `SearchHistoryRepository` aggregate several
  `*CrudRepository` tables and return *domain* models; entities never leave the data layer, and domain
  models never reach the CRUD repositories un-mapped.
- **`data/ApiService` is a data-layer service**, not a domain one — it works with raw API responses and
  entities. Don't confuse it with `service/SearchService`.
- Coroutines + `Flow` throughout (R2DBC + WebFlux). Repositories expose `Flow`; use cases collect.

Domain behaviour worth knowing: a `Search` expires one month after `updatedDate`
(`Search.isExpired()`), and `GetMoviesUseCase` decides between "refresh from OMDB", "first load", and
"serve from DB" based on that plus whether any movie references exist.

Persistence is in-memory H2 over R2DBC; the schema is created from `backend/src/main/resources/schema.sql`
(`movies`, `search_history`, `search_movies` join table). Data does not survive a restart.

Errors are always `application/problem+json`. `GlobalExceptionHandler` injects `timestamp` and
`requestId` into every `ProblemDetail`; problem `type` URIs are documented by `ProblemTypesController`.

### Backend conventions

- **detekt requires KDoc on every public class, function, and property**
  (`UndocumentedPublicClass/Function/Property` are active in `backend/config/detekt/detekt.yml`).
  Undocumented public API fails the build.
- **MockK, not Mockito** — `mockito-core` is explicitly excluded from the test classpath. Use
  `mockk`/`coEvery`/`coVerify`, and `@MockkBean` (springmockk) inside Spring contexts.
- Test naming: `*Test.kt` for isolated unit tests, `*IntegrationTest.kt` for `@SpringBootTest`.
  Test functions use backticked sentences — `` `when saving search, given query, then ...` `` — with
  `// Given` / `// When` / `// Then` comment blocks.
- Test fixtures are `testXxx()` factory functions in per-package `TestUtils.kt` files.
- `ApiClient` integration tests use WireMock (`wiremock-spring-boot`).
- The project targets JDK 17 via toolchain (CI provisions JDK 21).

## Frontend architecture

Angular 22 standalone components with signals; no NgModules, no state library.

```
services/    api.service.ts     — thin HTTP layer, one method per backend endpoint, returns Observables
             movies.service.ts, search.service.ts — domain services: validate input, own error signals
components/  movies-container   — smart container wiring services to presentational children
             movies-grid, search-history — presentational
models/      TypeScript mirrors of the backend DTOs (incl. problem-detail.model.ts)
utils/       api.utils (error extraction), signal.utils (delayedSignal), date.utils, url.utils
```

Errors surface as `signal<string | null>` on the domain services, populated via
`extractErrorMessage()` from the backend `ProblemDetail` payload.

`frontend/.junie/guidelines.md` holds the full Angular style guide for this project. The parts that
matter most here:

- Standalone components only; never set `standalone: true` (default in v20+).
- `input()` / `output()` functions, not decorators. Host bindings go in the `host` object, not
  `@HostBinding` / `@HostListener`.
- `ChangeDetectionStrategy.OnPush` on every component; signals for state, `computed()` for derived
  state, `update`/`set` (never `mutate`).
- `inject()` over constructor injection; `providedIn: 'root'` for singletons.
- Native control flow `@if` / `@for` / `@switch`, not `*ngIf` / `*ngFor` / `*ngSwitch`. No arrow
  functions in templates. `class`/`style` bindings, not `ngClass`/`ngStyle`.
- Reactive forms over template-driven; `NgOptimizedImage` for static images.
- Accessibility is enforced by lint (`angular.configs.templateAccessibility`) — WCAG AA and AXE-clean.
- Strict TypeScript; avoid `any`, prefer `unknown`.

Formatting comes from the Prettier block in `frontend/package.json` (100 columns, single quotes).
Component selectors must be `app-` kebab-case; directive selectors `app` camelCase.
